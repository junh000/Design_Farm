# 현재 NCP 서버 배포

`deploy-release.sh`는 `/opt/design-farm/current`와 `design-farm-api`, `design-farm-web` 서비스를 사용하는 기존 서버용이다. root로 실행하며, 배포할 애플리케이션의 **전체 40자리 커밋 SHA**를 인수로 전달한다. 스크립트를 가져온 커밋과 애플리케이션 커밋은 달라도 된다. 검토·CI·병합이 끝난 커밋을 사용한다.

```bash
bash deploy-release.sh <40자리-커밋-SHA>
```

- 현재 연결된 릴리스를 읽어 이전 버전으로 기록한다. 새 코드는 `releases/20261108-<SHA 앞 7자리>`에 내려받아 별도로 설치·검사·빌드한다. 이 단계에서는 서비스가 계속 실행된다.
- 현재 서버의 보안 쿠키·허용 출처 설정, 레이아웃, `test_hosting.py`를 보존한다. 배포용 수정이므로 `DEPLOYED_COMMIT`은 원본 소스 커밋을 의미한다. Caddy 설정은 검증하고 그대로 둔다. 기존 25MB 제한과 비활성화된 관리자 API를 변경하지 않는다.
- 백엔드 테스트를 모두 검색하여 실행한다. 일반 테스트는 로컬 쿠키 설정, 보존한 호스팅 테스트는 기존 보안 설정으로 각각 실행한다. 다각도 사진 실험 테스트, 프런트엔드 전체 `*.test.mjs`, 타입 검사 및 빌드도 실행한다. 실제 생성 API를 사용하지 않는다.
- 활성화 직전에 서비스를 멈추고 DB·업로드 전체 압축본, SQLite 백업, 주요 테이블별 행 수를 권한이 제한된 `backups/<릴리스>/activation-*`에 기록한다. `current` 심볼릭 링크를 원자적으로 바꾸고 서비스를 시작한다. 건강 상태·행 수·DB 무결성·생성 기능 비활성화를 확인한다.
- 실패하면 이전 코드와 생성 비활성화 설정을 복원하고 서비스를 재시작한다. 새 버전의 DB 변경은 추가 테이블뿐이므로 DB를 자동으로 되돌리지 않는다. 점검 중 접수된 회원·작품 데이터를 잃지 않도록 데이터 백업 복원은 별도 판단한다.

빌드가 완료된 후 활성화 단계에서 실패한 경우에만 같은 SHA로 다시 활성화할 수 있다. 현재 릴리스가 최초 기록과 다르면 중단한다.

```bash
bash deploy-release.sh <동일한-40자리-커밋-SHA> --activate-only
```

유료 생성 요청을 막기 위해 `/etc/systemd/system/design-farm-api.service.d/95-generation-off.conf`에서 `DESIGN_FARM_GENERATION_ENABLED`와 `DESIGN_FARM_MESHY_API_KEY`를 서비스 환경에서 제거한다. 향후 생성 기능을 켜려면 운영자가 이 차단 설정을 제거하고, 키·사용 동의·비용 한도를 별도로 검토한 후 서비스를 다시 시작해야 한다.

스크립트는 `bash -n`과 내장 Python 구문 검사로 정적으로 검증한다. 실제 배포 성공 여부는 서버에서 출력되는 `DEPLOYMENT_COMPLETE_<SHA>` 및 공개 웹사이트 점검으로 확인한다. 실행 기록에 비밀키나 DB 내용을 붙이지 않는다.
