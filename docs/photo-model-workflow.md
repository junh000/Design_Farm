# 사진 → 3D 모형 등록 연동

## 현재 제공 범위

작품 등록 화면에서 **사진으로 3D 모형 만들기**를 펼치면 같은 작품의 정면·오른쪽·뒷면·왼쪽 사진을 받는 흐름을 볼 수 있다. 기본 설정은 비활성화이며, 실제 배포에서도 외부 전송과 유료 생성을 차단한다. 기존 사진 등록·GLB 직접 첨부·등록 전 미리보기는 계속 사용할 수 있다.

연동 활성화 이후의 구현 흐름은 사진 4장 → 전송 동의 → 생성 대기/진행률 → 원본 4장과 모형 회전 비교 → 사용자 채택 → 등록 전 미리보기 → 최종 등록이다. 생성 모형 비교 화면은 원래 비율을 보존한다. 공개 전 미리보기와 구매자 공간 배치에서는 등록한 cm 치수를 적용한다. 생성 결과 자체가 실측 크기나 정확한 형상을 보증하지 않는다.

## 운영 설정

- 서버 전용 `DESIGN_FARM_MESHY_API_KEY`와 `DESIGN_FARM_GENERATION_ENABLED=1`이 모두 있어야 요청 가능하다. 키만 설정하면 활성화되지 않는다. 클라이언트 환경 변수에 키를 넣지 않는다.
- 네이버 배포 스크립트는 두 변수를 서비스 환경에서 제거하는 별도 설정을 설치한다. 향후 실제 연동 시 해당 운영 설정을 명시적으로 변경해야 한다.
- 이 버전은 **Uvicorn 단일 프로세스/단일 worker** 운영을 전제로 한다. 여러 worker 또는 서버로 확장하기 전에 시작 시 복구와 작업 잠금 구조를 변경해야 한다.
- API는 최대 4장을 받으므로 정확히 4장을 사용한다. 8장 이상을 조용히 잘라 보내지 않는다. 추가 각도는 [실험 절차](multiview-experiment.md)의 품질 대조 사진으로 보관한다.
- 모델/옵션은 `meshy-7.1`, `meshy-7` 텍스처, 표준 해상도, 30,000 목표 폴리곤, GLB로 고정한다. 자동 실측 추정은 끈다.
- 비용은 서비스의 현재 요금 및 결과 사용량에 따른다. 화면의 크레딧은 **최근 생성 시도 1회**의 반환값이며 전체 누적 청구액이 아니다. 재시도도 새 유료 요청에 동의해야 한다.

## 저장·접근·중복 방지

- 작업·요청 번호·시도 이력은 기존 SQLite에 별도 테이블로 저장한다. 입력 사진은 기존 업로드 경로, 검토 모형은 `generation-results`에 저장한다.
- 본인이 올린 서로 다른 사진만 요청할 수 있다. 작업과 검토 모형은 소유자만 조회한다. 채택 시 기존 GLB 첨부 체계로 복사하며, 최종 작품 등록 전에는 구매자에게 공개되지 않는다.
- 요청 UUID와 사진 내용 해시로 중복 제출을 차단한다. 진행/확인 필요 작업은 사용자당 1개, 전체 4개로 제한한다. 최근 24시간 시도는 사용자당 3회, 전체 10회다. 보관 작업은 사용자당 10개, 전체 100개이며 자동 삭제하지 않는다.
- 대기 작업을 먼저 제출한 뒤 가장 오래 확인하지 않은 작업부터 조회한다. 대기 15분 초과는 미전송 실패, 원격 작업 확인 2시간 초과는 운영자 확인 대상으로 전환한다.
- POST 응답 유실·서버 오류·전송 중 재시작은 `needs_review` 상태로 남기고 자동 재전송하지 않는다. 운영자가 공급자 작업 내역을 확인해야 한다. 알려진 작업 번호만 조회를 재개한다.
- 생성 파일은 승인된 HTTPS 호스트에서만 받으며 리디렉션, 비공개 IP, 20MB 초과 및 지원하지 않는 GLB를 차단한다. 다운로드에 API 키를 전달하지 않는다.

## 검증과 남은 작업

백엔드 검사는 외부 서비스를 모의 구현해 비활성 상태, 소유권, 동의, 중복/동시 제출, 재시도·복구, 공정한 작업 처리, 비공개 검토, 채택 및 등록 후 공개, 다운로드 검증을 확인한다. 실제 API 호출이나 과금은 없다. 기본 비활성 등록 화면은 로컬 브라우저에서 확인했다.

실제 작품 사진과 서비스 키가 준비되면 #6에서 생성 품질·비용·소요시간을 기록하고, #7에서 실제 생성 → 비교 → 채택 → 등록 → 구매자 3D/AR 흐름을 검증해야 한다. 현 단계에서는 두 이슈의 실제 서비스 검증 항목을 완료로 처리하지 않는다.
